# 03 - API Specification

Base URL: `/api/v1/`
Schema: generated by `drf-spectacular`, served at `/api/schema/` and browsable at
`/api/docs/`.

## 1. Conventions

| Aspect | Rule |
|---|---|
| Format | JSON only, `snake_case` keys |
| Dates | ISO-8601 with timezone, e.g. `2026-08-18T10:15:00+02:00` |
| Distance | metres, integer |
| Duration | minutes, integer |
| Coordinates | `lat` and `lng`, decimal degrees, WGS-84 |
| Money | integer RWF, no decimals |
| Staleness | any payload with derived live data carries `as_of` |

### Error body

```json
{
  "type": "validation_error",
  "detail": "lat must be between -2.9 and -1.0",
  "field": "lat"
}
```

| HTTP | `type` | When |
|---|---|---|
| 400 | `validation_error` | Bad or missing parameter |
| 401 | `authentication_required` | Missing or expired token |
| 403 | `permission_denied` | Staff acting outside their facility |
| 404 | `not_found` | Unknown or unverified resource |
| 409 | `conflict` | Slot taken, already checked in |
| 429 | `rate_limited` | Includes `Retry-After` |
| 503 | `service_unavailable` | Dependency down; clients show cached data |

## 2. Authentication

| Client | Method |
|---|---|
| Patient PWA | JWT via OTP - phone number, then a 6-digit SMS code |
| Provider web | JWT via username + password |
| USSD / WhatsApp webhooks | Shared secret header + source-IP allowlist |
| Django admin | Session auth, staff only |

### `POST /auth/otp/request`

```json
{ "phone": "+250788123456" }
```

Always returns `204`, whether or not the number is known - do not leak which
numbers are registered. Rate-limited to 3 requests per number per 15 minutes.

### `POST /auth/otp/verify`

```json
{ "phone": "+250788123456", "code": "483927" }
```

```json
{
  "access": "eyJhbGciOi...",
  "refresh": "eyJhbGciOi...",
  "patient": { "id": 4821, "full_name": "", "language": "rw", "insurer": null }
}
```

Five wrong attempts invalidate the code. Codes expire after 5 minutes.

### `POST /auth/token/refresh`

Standard SimpleJWT refresh. Access token lifetime 60 minutes, refresh 30 days.

## 3. Facilities

### `GET /facilities/nearby` - the primary discovery endpoint

Full design rationale in [04-nearby-facilities.md](04-nearby-facilities.md).

| Parameter | Type | Required | Default | Notes |
|---|---|---|---|---|
| `lat` | float | yes | - | -2.9 to -1.0 (Rwanda bounds) |
| `lng` | float | yes | - | 28.8 to 30.9 |
| `radius` | int (m) | no | 5000 | max 50000 |
| `insurer` | string | no | - | Insurer `code`; filters strictly |
| `service` | string | no | - | ServiceType `code` |
| `level` | string | no | - | Repeatable |
| `open_now` | bool | no | false | |
| `limit` | int | no | 20 | max 50 |

```
GET /api/v1/facilities/nearby?lat=-1.9536&lng=30.0606&insurer=mutuelle&radius=5000
```

```json
{
  "as_of": "2026-08-18T10:12:04+02:00",
  "query": {
    "lat": -1.9536, "lng": 30.0606,
    "radius": 5000, "radius_expanded": false,
    "insurer": "mutuelle"
  },
  "count": 12,
  "results": [
    {
      "id": 118,
      "slug": "kimironko-health-centre",
      "name": "Kimironko Health Centre",
      "level": "health_centre",
      "ownership": "public",
      "district": "Gasabo",
      "sector": "Kimironko",
      "location": { "lat": -1.9481, "lng": 30.1122 },
      "distance_m": 1240,
      "phone": "+250788000111",
      "is_open": true,
      "opens_at": "07:00",
      "closes_at": "17:00",
      "accepts_insurer": true,
      "insurers": ["mutuelle", "rssb", "mmi"],
      "services": ["general_consultation", "maternity", "laboratory"],
      "wait": {
        "status": "available",
        "minutes": 40,
        "people_waiting": 14,
        "as_of": "2026-08-18T10:11:30+02:00"
      },
      "bookable": true
    },
    {
      "id": 205,
      "name": "Remera Polyclinic",
      "distance_m": 2810,
      "is_open": true,
      "accepts_insurer": true,
      "wait": { "status": "not_reported", "minutes": null },
      "bookable": false
    }
  ]
}
```

**`wait.status` is a closed enum and the UI must handle all four:**

| Value | Meaning | UI copy |
|---|---|---|
| `available` | Live data, sufficient sample | "About 40 min" |
| `not_reported` | Facility does not run our reception tool | "Wait time not available" |
| `insufficient_data` | Runs the tool, but under 20 samples | "Wait time not available yet" |
| `closed` | Facility closed now | "Closed - opens 07:00" |

There is deliberately **no** value meaning "estimated". We never guess.

### `GET /facilities/{slug}`

Full detail: all services, all opening hours, all insurers, live wait, next
available bookable slots (5), directions link, verification date.

### `GET /facilities/{slug}/slots`

| Parameter | Required | Notes |
|---|---|---|
| `service` | yes | ServiceType code |
| `date_from` | no | Defaults to today |
| `date_to` | no | Defaults to `date_from` + 14 days, max 30 |

```json
{
  "facility": "kimironko-health-centre",
  "service": "general_consultation",
  "days": [
    {
      "date": "2026-08-19",
      "slots": [
        { "start": "08:00", "end": "08:15", "remaining": 2 },
        { "start": "08:15", "end": "08:30", "remaining": 0 },
        { "start": "08:30", "end": "08:45", "remaining": 3 }
      ]
    }
  ]
}
```

Slots with `remaining: 0` are returned rather than omitted, so the UI can show
them greyed out - patients need to see that a day is busy, not that it is empty.

### `GET /insurers` and `GET /service-types`

Small, cacheable reference lists. Include all three language names so USSD and
WhatsApp can render them without a second call.

```json
{
  "results": [
    { "code": "mutuelle", "name": "Mutuelle de Sante", "is_public": true },
    { "code": "rssb",     "name": "RSSB",              "is_public": true },
    { "code": "mmi",      "name": "MMI",               "is_public": true }
  ]
}
```

## 4. Appointments (patient)

### `POST /appointments`

```json
{
  "facility": "kimironko-health-centre",
  "service": "general_consultation",
  "slot_start": "2026-08-19T08:00:00+02:00"
}
```

`201`:

```json
{
  "id": 9912,
  "reference": "ML7K2Q",
  "status": "booked",
  "facility": { "name": "Kimironko Health Centre", "phone": "+250788000111" },
  "slot_start": "2026-08-19T08:00:00+02:00",
  "slot_end": "2026-08-19T08:15:00+02:00"
}
```

`409 conflict` if the slot filled between the read and the write. The booking is
wrapped in `select_for_update()` on the slot's appointment count - two patients
tapping the last slot simultaneously must not both succeed.

### `GET /appointments` / `GET /appointments/{id}` / `POST /appointments/{id}/cancel`

`GET /appointments` returns the caller's own appointments, `?status=upcoming` by
default. Cancellation is allowed until `slot_start`; afterwards the endpoint
returns `409` and the facility marks it a no-show.

## 5. Queue

### `POST /queue/entries` - reception check-in (staff only)

The single most performance-sensitive write in the system. Target: **under 10
seconds of total human time**, so the payload must be minimal.

```json
{ "service": "general_consultation", "phone": "+250788123456" }
```

or, for a walk-in with no phone:

```json
{ "service": "general_consultation", "walk_in_name": "Uwase Alice" }
```

or, checking in an existing appointment:

```json
{ "appointment_reference": "ML7K2Q" }
```

`201`:

```json
{
  "id": 55210,
  "ticket_code": "A-042",
  "position": 9,
  "eta_minutes": 45,
  "status": "waiting",
  "as_of": "2026-08-18T10:12:04+02:00"
}
```

`facility` is never in the request body - it is derived from the authenticated
staff member. A receptionist cannot check a patient into another facility.

**Idempotency:** the client sends `Idempotency-Key`. A retry after a network
timeout must return the original entry, not create a duplicate. This matters
because reception networks drop constantly.

### `GET /queue/entries/{id}` - the patient's live view (polled every 20 s)

```json
{
  "id": 55210,
  "facility": {
    "name": "Kimironko Health Centre",
    "location": { "lat": -1.9481, "lng": 30.1122 }
  },
  "service": "general_consultation",
  "ticket_code": "A-042",
  "status": "waiting",
  "position": 8,
  "people_ahead": 7,
  "eta_minutes": 35,
  "eta_confidence": "medium",
  "leave_by": "2026-08-18T10:15:00+02:00",
  "travel_minutes": 18,
  "joined_at": "2026-08-18T09:40:00+02:00",
  "as_of": "2026-08-18T10:12:04+02:00"
}
```

`leave_by` is null when travel time cannot be computed (no patient location).
`eta_confidence` is `high | medium | low` and is derived from `sample_size` and
the variance of recent service times. The UI widens its language as confidence
falls: "about 35 min" at high, "roughly 30-50 min" at low.

Responds `304 Not Modified` against `If-None-Match` when nothing changed - this
is what keeps 20-second polling cheap.

### `GET /queue/current`

Returns the caller's single active queue entry, or `204` if none. This is what
the patient home screen calls on load to decide between State A and State B
(see [05-frontend-specification.md](05-frontend-specification.md)).

### Staff queue operations

| Endpoint | Action |
|---|---|
| `GET /queue/board` | The full waiting list for the staff member's facility, grouped by service |
| `POST /queue/entries/{id}/call` | Mark `called`, stamp `called_at`, trigger SMS |
| `POST /queue/entries/{id}/serve` | Mark `served`, stamp `served_at`, feed `ServiceTimeStat` |
| `POST /queue/entries/{id}/skip` | Mark `left`, patient did not answer |
| `POST /queue/entries/{id}/cancel` | Mark `cancelled` with a reason |

### `POST /queue/sync` - offline reconciliation

The reception client posts an array of locally recorded actions with client
timestamps and idempotency keys after reconnecting. The server applies them in
`client_recorded_at` order and returns per-item results, so one rejected item
does not fail the whole batch.

```json
{
  "actions": [
    { "key": "a1f2...", "type": "check_in", "client_recorded_at": "...", "payload": {} },
    { "key": "b7c4...", "type": "serve",    "client_recorded_at": "...", "payload": {} }
  ]
}
```

## 6. Patient profile

| Endpoint | Purpose |
|---|---|
| `GET /me` | Profile: name, language, insurer, home location |
| `PATCH /me` | Update any of the above |
| `GET /appointments` | Past and upcoming appointments. (Documented here as `/me/visits` until 2026-09-02; the implemented route is `/appointments`, and the Visits screen uses it.) |
| `GET /me/notifications` | Notification history |
| `GET /me/notification-preferences` | Channel preferences |
| `GET /me/export` | Data export - see doc 08 |
| `DELETE /me` | Account deletion request - see doc 08 |

### Specified but NOT implemented

Audited 2026-09-02 against the registered URLconf. These two appear in earlier
drafts of this document and have no route:

| Endpoint | Status |
|---|---|
| `POST /me/push-subscription` | Web Push is modelled - `NotificationChannel.PUSH` exists - but there is no subscription endpoint, no VAPID keypair and no service-worker push handler. Notifications reach patients by the channels in doc 06. |
| `POST /gateway/sms-status` | No SMS delivery-receipt webhook. Delivery is not currently confirmed back from the gateway. |

Do not build against either without checking this table again.

## 7. Triage (Phase 4)

### `POST /triage/sessions` and `POST /triage/sessions/{id}/answer`

Rule-based, deterministic, and versioned. The response always carries a
disclaimer string and, when relevant, an escalation flag.

```json
{
  "session_id": "d81f...",
  "next_question": {
    "code": "chest_pain_duration",
    "text_rw": "Umutima wawe umaze igihe kingana iki ubabara?",
    "options": [ { "code": "lt_1h", "text_rw": "Munsi y'isaha" } ]
  },
  "recommendation": null,
  "escalate_emergency": false,
  "protocol_version": "2026.1",
  "disclaimer_rw": "Ibi si ubuvuzi. Niba bikomeye, jya kwa muganga ako kanya."
}
```

When `escalate_emergency` is `true`, the client must abandon the flow and show
emergency guidance immediately. This is a hard client requirement, not a
suggestion.

## 8. Webhooks (inbound)

| Endpoint | Source | Auth |
|---|---|---|
| `POST /gateway/ussd` | USSD aggregator | Shared secret + IP allowlist |
| `POST /gateway/whatsapp` | Meta Cloud API | `X-Hub-Signature-256` HMAC |
| `GET /gateway/whatsapp` | Meta verification handshake | `hub.verify_token` |

These return plain text (USSD) or `200 OK` fast. Never do slow work inline -
queue it to Celery and return immediately, or the aggregator times out and the
patient sees a blank screen. Details in
[06-channels-ussd-whatsapp.md](06-channels-ussd-whatsapp.md).

## 9. Rate limits

| Scope | Limit |
|---|---|
| `GET /facilities/nearby` (anonymous) | 60/min per IP |
| `GET /queue/entries/{id}` (authenticated) | 10/min per entry - covers 20 s polling with headroom |
| `POST /auth/otp/request` | 3 per phone per 15 min, 20 per IP per hour |
| `POST /appointments` | 10 per patient per day |
| Staff endpoints | 600/min per facility |
